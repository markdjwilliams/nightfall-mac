# Public beta and testing review

Mark approved making the repository public on **October 28, 2026**, superseding the earlier plan to keep it private until November 11. Nightfall remains an early beta. The two-week test period began October 28, with a testing follow-up planned for **November 11, 2026**. Do not infer successful testing from public availability or a lack of messages.

## Test evidence

- After the November 3 cold boot, the installed 1.1.2 root service still omitted display/input evidence six hours after login. Version 1.1.3 uses a protected probe in the active desktop’s context instead of calling desktop APIs from the system service.
- On November 3, a temporary root LaunchDaemon using the production default security session returned valid probe evidence in 17 ms, within the 800 ms deadline. The installed 1.1.3 build 7 app and helper matched the verified Intel build, their signatures passed, and the shared schedule and cancellations were preserved. The installed service detected sleeping displays in all nine samples of a brief controlled display-off test, then detected waking displays in all four recovery samples. Neither test requested system sleep. The next cold boot/login remains unverified for this version. A nested `bsexec`/`asuser` diagnostic failed before reaching the probe; it was not used as production evidence.
- The first overnight check of 1.1.3 confirmed actual scheduled sleep on November 3 at 20:30:15, attributed by macOS to Nightfall's installed daemon. The app requested sleep at 20:30:00; macOS's 15-second transition hold then expired. Through 08:00 the following morning, macOS recorded 19 maintenance dark wakes lasting 44–45 seconds each, totaling 14 minutes 14 seconds, with a return to sleep after every one and no full wake in that interval. Power Nap had been disabled separately on the test Mac. This confirms one successful scheduled sleep, not uninterrupted sleep or measured fan silence. Cancellation, user switching and cold-boot behavior still need field verification.
- The 1.1.3 source passed local scheduling, model, system-presence, dry-run service and packaging checks, plus [GitHub Actions run 6](https://github.com/markdjwilliams/nightfall-mac/actions/runs/41725298740), including isolated installation/removal checks and both app architectures. Cross-building still does not establish Apple Silicon runtime behavior.

- On October 30, macOS recorded actual software sleep at 20:30:15 requested by the installed Nightfall service. This confirms one successful automatic sleep on the Intel field-test Mac, not complete coverage of interactive or overnight behavior.
- On November 1, version 1.1.2 consumed the occurrence at 20:28:10 because its warning was not confirmed visible. The display stayed awake until 20:37, so the later screen-off state could not recover that occurrence. Version 1.1.3 retains a pending occurrence until the next daily warning and requires a new full countdown after recovery. Installed field verification remains required.
- On November 2, the Mac was already asleep from 20:25 to 20:50. Nightfall recorded a missed warning on waking; subsequent maintenance wakes included XProtect and hour-long media-analysis jobs. Manual sleep requests were accepted without an immediate full-sleep transition. At 03:10 on November 3, media analysis and its CPU hold ended immediately before maintenance sleep. This strongly implicates maintenance holds but does not identify a veto for every individual manual request.

- The first 1.1.2 updater attempt on October 29 stopped before replacement because macOS returned a signed-out GUI-session response the installer did not recognize. Beta 2 adds that response to the GUI-only absence checks while retaining stop verification and fatal handling for permission or system-service errors.
- The first field test on October 28 failed to request scheduled sleep: version 1.1.0 consumed the occurrence when its warning could not be presented while the Mac was idle with sleeping displays. This is a reported failure, not evidence of a completed testing period. Version 1.1.2 addresses that case with independently sampled display/input evidence and a full unattended interval; additional installed scenarios still need confirmation.
- Obtain Mark's report of the two-week test period and resolve any reported problems.
- Confirm real sleep, one-occurrence cancellation, tomorrow's schedule, multiple logged-in users, user switching, screen locking, full-screen apps, and restart behavior on the destination Mac. Keeping keyboard focus in another application must not cancel a warning that remains usable, visible, not occluded, and on the active desktop; **Skip tonight** must work on the first click in its inactive window. Automated tests and rendered previews do not establish these interactive results.
- Confirm the installed root service detects all online displays asleep and no input for a full unattended warning interval. Return partway through, wake one of several displays, and switch console users; each must revoke unattended approval and require a full visible warning for an awake user. If the displays sleep again while the occurrence is pending before the next daily warning, a new full unattended interval may start; no earlier elapsed time may carry over. A skipped or cleared occurrence must never return. An awake display must retain the visible-warning requirement even during long reading or video sessions. Unknown/failed readings cannot authorize unattended sleep; if neither usable presentation nor valid unattended evidence becomes available, the occurrence must wait without approving sleep and expire when the next daily warning is due. These hardware and session transitions remain manual checks.
- Re-run the scheduling, app-model, system-presence probe, dry-run service, isolated installer/uninstaller, and packaging checks. Injected samples and probe failures cover decision logic; they do not establish the root service's real display/input observations. Do not trigger real sleep or uninstall as part of an unattended release review.
- State tested hardware and macOS versions accurately. The field-test Mac is Intel-based. Downloads are built separately for Intel and Apple Silicon; Apple Silicon hardware has not been tested. Cross-compilation and signature checks do not establish native runtime behavior or constitute a universal binary release.

## Licensing and public content

- MIT was selected by Mark on October 28. Preserve `LICENSE` and `NOTICE.md` in source distributions and compiled app bundles.
- Review new dependencies, copied code, and assets. The initial source/history scan found no bundled third-party packages or media, detected secrets, or personal machine paths. This is a bounded source audit, not legal clearance or a guarantee of originality.
- Keep Apple system symbols in permitted interface roles. Review any branding use against Apple's current SF Symbols restrictions; use the original application artwork for app identity. Do not redistribute Apple system assets under MIT.
- Git history includes its original commit author metadata. Do not silently rewrite history; agree on any identity changes or cleanup with Mark first.
- Review new source, artifacts and Git history for secrets and unintended personal data before later releases.
- Developer ID signing and notarization are separate distribution decisions. The current build is ad hoc signed, as the README states.
